# Newsletter subscriptions

The shared homepage/footer form posts real subscriptions to MongoDB through `/api/newsletter`. The existing **Admin → Newsletter** menu at `/admin/newsletter` manages the same records. Membership and volunteer email records do not automatically imply newsletter consent; a person can subscribe without creating another member or volunteer account.

Email is trimmed and lowercased. Existing newsletter addresses are matched case-insensitively. An active duplicate receives a specific 409 response without another confirmation. A previously unsubscribed address also receives a specific response and remains unsubscribed. Public requests cannot set admin sources, metadata, status or tokens. The form includes a honeypot, and public mutations reject cross-site origins.

A new subscription and its confirmation outbox message commit in the same MongoDB transaction. The unique email index and per-subscription-version message index prevent duplicate records and mail under concurrent submissions. Confirmation uses the existing real Sendridge adapter (`SENDRIDGE_API_KEY`, `EMAIL_FROM` or `SMTP_FROM`, optional `EMAIL_REPLY_TO`, `NEXT_PUBLIC_SITE_URL`). No new email credentials are required. The UI distinguishes a sent confirmation from a saved subscription whose email is queued.

Each confirmation contains a random, private unsubscribe link. Only its SHA-256 hash is kept on the subscriber; the raw link exists in the queued email body and the recipient’s email. Public/admin API responses exclude the token hash and email body. The URL fragment keeps the token out of HTTP URLs/referrers. Opening the unsubscribe page performs no mutation; pressing Unsubscribe posts the token without requiring a login. Repeating an unsubscribe is safe. Opt-out keeps a dated subscriber record, stops pending confirmations, and excludes the address from the existing active-subscriber notification audience. It does not unsubscribe a membership or volunteer account.

The admin page supports search, source/status filters, filtered CSV export, manual additions, unsubscribe, explicit reactivation, deletion, confirmation status and retries. CSV exports quote fields and neutralize spreadsheet formulas. Reactivation sends a fresh confirmation and rotates the unsubscribe token, so an old link cannot cancel a new subscription. Already delivered confirmations are not resent by Retry. Legacy subscribers are not emailed automatically; an admin can explicitly send their first confirmation. Deletion also removes stored newsletter confirmation messages.

`/api/cron/newsletter-notifications` retries pending/failed messages with delivery leases, checking current subscription status/version immediately before sending. It uses the existing `CRON_SECRET` and a daily Vercel cron at 08:45 UTC. Admins can retry a specific confirmation immediately. As with other app outboxes, a process crash after provider acceptance but before marking delivery can cause a duplicate; normal replay of a completed message is suppressed.

Validation commands (PowerShell):

- `$env:RUN_NEWSLETTER_DB_TEST='1'; npm run test:newsletter:integration` uses a uniquely named disposable MongoDB database, always mocks the email provider, and removes only that test database. It covers validation, twelve concurrent signups, duplicate prevention, rollback, email failure/retry, private opt-out, admin authorization, token rotation and deletion cleanup.
- `node scripts/check-newsletter.mjs` checks the homepage form, duplicate/queued states, unsubscribe page, admin actions/export and rendered contrast. It mocks every browser API write and email. Install Playwright locally or set `PLAYWRIGHT_MODULE` to its module directory; `ECP_TEST_URL` optionally overrides localhost:3000.
